# M2.5 Public Launch Checklist

> Date: 2026-06-13
> Target: same-domain public beta for the M2.5 mainline baseline.
> Branch/tag baseline: `reforge/main` / `m2.5-mainline-complete`.

## Launch Shape

Today ships the M2.5 usable beta, not the full M4 multiplayer product.

- Public domain with HTTPS.
- One domain serves the Vue app and proxies `/api/reforged/*` to `reforged-server`.
- `REFORGED_TOKEN` protects backend routes and room WebSocket upgrades.
- App data persists as JSON under `reforged-server/data/`.
- Room state and participant provider keys are still in memory and are lost on backend restart.

## What `REFORGED_TOKEN` Means

`REFORGED_TOKEN` is a temporary shared server password for this beta. The backend requires it on protected HTTP routes and WebSocket upgrades. Users enter the same value in Settings -> Reforged server token.

Use a long random value, for example:

```bash
openssl rand -base64 32
```

Do not commit the real token to git, docs, screenshots, or issue comments.

## Required DNS / Reverse Proxy Decision

Replace the placeholder domain below once the subdomain is created:

```text
https://<your-subdomain.example.com>
```

Use same-domain routing:

```text
https://<your-subdomain.example.com>/               -> app/dist static files
https://<your-subdomain.example.com>/api/reforged/* -> http://127.0.0.1:8787/api/reforged/*
```

With same-domain hosting, the frontend defaults to the current origin on public hosts. On localhost it still defaults to `http://127.0.0.1:8787` for development.

## Backend Runtime

Run the backend on loopback behind the reverse proxy:

```bash
export REFORGED_TOKEN="<long-random-token>"
export REFORGED_ALLOWED_ORIGIN="https://<your-subdomain.example.com>"
export REFORGED_GENERATION_MODE="proxy"
export REFORGED_PORT="8787"
node reforged-server/server.js
```

Notes:

- Do not set `REFORGED_ALLOWED_ORIGIN=*` for public launch.
- Keep the backend bound to `127.0.0.1`; expose it through the HTTPS reverse proxy.
- `REFORGED_GENERATION_MODE=stub` is only for smoke tests without real provider calls.

## Caddy Example

```caddyfile
<your-subdomain.example.com> {
  root * /absolute/path/to/SillyTavern/app/dist
  encode gzip zstd
  file_server

  reverse_proxy /api/reforged/* 127.0.0.1:8787
}
```

## Nginx Example

```nginx
server {
    server_name <your-subdomain.example.com>;

    root /absolute/path/to/SillyTavern/app/dist;
    index index.html;

    location /api/reforged/ {
        proxy_pass http://127.0.0.1:8787/api/reforged/;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }

    location / {
        try_files $uri $uri/ /index.html;
    }
}
```

## Browser Smoke Test

1. Open `https://<your-subdomain.example.com>`.
2. Go to Settings and enter the Reforged server token.
3. Leave the server URL blank for same-domain hosting, or set it to `https://<your-subdomain.example.com>`.
4. Reload once so app persistence can re-probe the backend with the token.
5. Confirm the storage status shows Reforged backend.
6. Go to Connection, set provider base URL, model, and provider API key.
7. Fetch models or test connection.
8. Import a character card.
9. Send a chat message and confirm the reply streams through `reforged-backend`.
10. Refresh the page and confirm chat/character data remains.
11. Open a second browser profile, enter the same server token, and confirm shared app data is visible while provider API key must be entered locally.
12. Create a room in one browser, join it from the second browser, and confirm message broadcast works.

## Known Launch Limits

- No account system yet.
- Room state is not durable across backend restarts.
- No host moderation surface yet.
- No rate limiting yet.
- Provider target allowlisting/private-IP blocking is not implemented yet; keep this beta private or token-gated.
- Users must protect their own provider API keys. Runtime keys are not committed or broadcast, but they are still sensitive local/browser input.

## Rollback

Keep the previous deployment directory or release tag available. To roll back:

1. Stop the backend process.
2. Restore the previous `app/dist` directory or checkout the previous tag.
3. Restart the previous backend command.
4. Keep `reforged-server/data/` backed up before replacing deployments.
