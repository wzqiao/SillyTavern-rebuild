## A 线：日常可玩性

### A1 模型列表 + 连接测试（连接页）
- `connectionStore` 增 action：`fetchModels()`（GET `{baseUrl}/models`，Bearer，浏览器直连；
  CORS 失败给出明确提示并允许手填回退）与 `testConnection()`（拉到模型列表即视为通过）。
- ConnectionView：模型输入框旁「获取模型列表」按钮 → 成功后模型字段变 Select（仍可手填）；
  「测试连接」按钮显示成功/失败与耗时。
- 文件：`connectionStore.ts`、`ConnectionView.vue`、i18n。测试：store action（mock fetch）。
- 验收：填 baseUrl+key → 点获取 → 下拉选模型 → 测试通过 → 应用。

### A2 对话示例（mes_example）接入
- `ReforgedCharacterCard` 增 `exampleMessages: string`（解析 `mes_example`/V2 V3 字段，缺省空串）。
- `ReforgedChatCharacterContext` 增 `exampleMessages?: string`；ChatView `toChatCharacter` 透传。
- 生成拼装：预设路径 `dialogueExamples` marker 输出解析后的示例（`<START>` 分块 →
  system 消息，`{{char}}/{{user}}` 宏替换）；legacy 路径在 system prompt 追加 Examples 段。
- 文件：`contracts/character.ts`、`contracts/chat.ts`、`parsers/characterCardJson.ts`、
  `chatGenerationService.ts`、`ChatView.vue`。测试：parser 字段 + 拼装两路径。
- 验收：导入带 mes_example 的卡，预设启用 dialogueExamples 时请求体含示例。

### A3 用户身份 Persona
- 新 `personaStore`：`{ name: string; description: string }`，kv 持久化（`persona.state`）。
- 宏替换：`{{user}}` → persona.name（缺省 'User'）；预设 `personaDescription` marker 输出
  description；legacy 路径 system prompt 追加 Persona 段；聊天气泡「我」标签显示 persona 名。
- 设置页「用户身份」分组从占位变可编辑（name + description 两个字段）。
- 文件：`stores/personaStore.ts`、`appPersistence.ts`、`chatGenerationService.ts`、
  `SettingsView.vue`、`ChatView.vue`、i18n。测试：持久化往返 + 拼装。
- 验收：设置 persona → 刷新保留 → 生成请求中 {{user}} 与 personaDescription 正确。

### A4 旧版聊天记录（jsonl）导入
- `parsers/chatJsonl.ts`：首行元数据 `{user_name, character_name, create_date}`，
  后续行 `{name, is_user, mes, send_date, swipes?, swipe_id?}` → 会话 + 消息
  （swipes → alternatives，send_date → createdAt，宽容解析带警告）。
- `chatStore.importSessionFromJsonl(input)`：建会话（按 character_name 匹配当前角色库，
  匹配不到则 character 为 null 并警告）。
- UI：会话抽屉「导入旧版聊天」按钮（文件选择 .jsonl）。
- 文件：`parsers/chatJsonl.ts(+test)`、`chatStore.ts`、`ChatView.vue`、i18n。
- 验收：导出一份旧版 ST 聊天 jsonl 导入后完整可读、swipe 可切换、刷新保留。

## B 线：后端转正

### B2 存储迁移到 reforged-server
- 服务端（`reforged-server/server.js`）新增存储路由（零新依赖，JSON 文件落盘 `reforged-server/data/`）：
  - `GET/PUT /api/reforged/storage/:store`（store ∈ characters/worldbooks/chat-sessions/chat-messages/presets，
    PUT 全量信封数组；GET 返回数组）
  - `GET/PUT /api/reforged/storage/kv/:key`
- 前端 `repositories/reforgedBackendRepository.ts`：实现 `ReforgedPersistenceGateway`（HTTP）。
- `startAppPersistence` 网关选择：探测 `/api/reforged/health`（超时 ~800ms）→ 可达用后端网关，
  否则 IndexedDB → 内存。设置页存储状态行显示三态。
- **密钥例外**：`connection.state` 的 `secrets` **不上传后端**，无论网关为何永远走本机 IndexedDB
  （ADR-006 边界：key 只落本机）。实现为 secrets 单独 kv 通道。
- 测试：HTTP 网关跑既有仓储契约测试（mock fetch / 内存 server）；server.test.js 增存储路由用例。
- 验收：起 8787 → 导角色聊天 → 关浏览器换一个浏览器打开 → 数据都在（key 除外，需重填）。

### B3 最小鉴权
- server 启动可配 `REFORGED_TOKEN`（或 `--token`）；设置后所有 `/api/reforged/*` 要求
  `Authorization: Bearer <token>`，WebSocket 走 query token。未设置则维持本机无鉴权。
- 前端：连接页或设置页「Reforged 服务地址 + 口令」字段（口令进内存金库 + 本机持久化，同 ADR-006）。
- 真正多账号体系留给 M4 主体，不在本计划。
