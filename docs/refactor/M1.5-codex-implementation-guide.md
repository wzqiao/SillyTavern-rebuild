## 1. 设计系统参考（照抄用，不要自创配色）

配色已在 `src/style.css` 用 Tailwind v4 `@theme` 把调色板**重定义为暖色**。你只管用下面的类名，颜色会自动是暖的。

### 1.1 语义 → 类名对照
| 用途 | 类名 | 效果 |
|---|---|---|
| 页面底色 | `bg-neutral-950` | 暖浓棕 #1C1714 |
| 卡片面 | `bg-neutral-900/80`、`bg-white/8` | 暖褐卡 |
| 抬升/输入底 | `bg-neutral-950/60` | 更深暖底 |
| 正文 | `text-neutral-100` / `text-neutral-50` | 暖奶白 |
| 次要文字 | `text-neutral-400` | 暖灰 |
| 更次要/占位 | `text-neutral-500` | |
| 边框/分隔 | `border-white/10`、`border-white/8` | 暖奶白细线 |
| **品牌/强调/主按钮/用户气泡** | `bg-cyan-300 text-neutral-950`、`text-cyan-100`、`border-cyan-300/30` | 蜜糖灯光（cyan 已被重定义为蜜糖色，照旧用 cyan-* 即可） |
| 警告 | `*-amber-400`、`text-amber-100` | 暖金 |
| 成功 | `*-emerald-400` | 沙绿 |
| 危险/错误 | `*-rose-400` | 暖珊瑚红 |

> ⚠️ 关键认知：模板里继续写 `cyan-*` 就是蜜糖色，写 `amber-*` 就是暖金——因为 token 被覆盖了。**不要**为了“暖”去把 cyan 改成 amber，多此一举且会撞警告色。

### 1.2 招牌元素：灯晕
活动/正在生成的元素加类 `lamp-glow`（已在 style.css 定义），得到柔和暖光描边。用在：正在流式的消息气泡、空态图标。

### 1.3 字体（本次要新增——暖色衬线 display）
目标：标题、角色名用一款有气质的暖色衬线，正文保持无衬线。中文需可读。

**步骤 1** — `index.html` `<head>` 内加（放在 `<title>` 后）：
```html
<link rel="preconnect" href="https://fonts.googleapis.com" />
<link rel="preconnect" href="https://fonts.gstatic.com" crossorigin />
<link href="https://fonts.googleapis.com/css2?family=Noto+Serif+SC:wght@500;600;700&display=swap" rel="stylesheet" />
```
> index.html 不在禁改清单里，可改。离线时会回退到系统衬线，可接受；将来可自托管。

**步骤 2** — `src/style.css` 的 `@theme {}` 内加：
```css
  --font-display: "Noto Serif SC", "Songti SC", "STSong", ui-serif, serif;
```
Tailwind v4 会据此生成 `font-display` 工具类。

**步骤 3** — 应用范围（只给“标题气质”，别全局）：角色名、页面大标题、空态标题加 `font-display`。正文、按钮、表单**不要**加。

### 1.4 形状约定（保持一致）
- 卡片圆角：`rounded-[1.5rem]`；气泡：`rounded-[1.35rem]`；输入区：`rounded-[1.6rem]`；小控件：`rounded-xl`/`rounded-full`。
- 触控目标 ≥ 40px（`min-h-10` 以上）。
- 卡片阴影：`shadow-[0_18px_70px_rgba(0,0,0,0.28)]` 一类的柔和暖阴影。

## 2. i18n 架构（中英可切换，零依赖——本次要新建）

现状：`src/i18n/zh.ts` 是纯中文对象。要做成中英可切换。

### 2.1 目标文件结构
```
src/i18n/
  zh.ts        // 已存在，中文词典（继续扩充）
  en.ts        // 新建，英文词典，类型 = typeof zh，编译器强制键对齐
  index.ts     // 新建，useI18n composable + setLocale
```

### 2.2 `src/i18n/index.ts`（照抄）
```ts
import { computed, ref } from 'vue';
import { zh } from './zh';
import { en } from './en';

export type Locale = 'zh' | 'en';
const STORAGE_KEY = 'st-reforged-locale';

function readInitial(): Locale {
  const saved = globalThis.localStorage?.getItem(STORAGE_KEY);
  return saved === 'en' ? 'en' : 'zh'; // 默认中文
}

const locale = ref<Locale>(readInitial());
const dicts = { zh, en } as const;
const messages = computed(() => dicts[locale.value]);

export function setLocale(next: Locale): void {
  locale.value = next;
  globalThis.localStorage?.setItem(STORAGE_KEY, next);
}

export function useI18n() {
  return { t: messages, locale, setLocale };
}
```

### 2.3 `src/i18n/en.ts`（结构必须与 zh 完全一致）
```ts
import type { Zh } from './zh';
export const en: Zh = {
  app: { name: 'ST-Reforged', tagline: 'Cozy chats with your characters' },
  nav: { chat: 'Chat', characters: 'Characters', /* …逐键翻译… */ },
  // …其余键与 zh 一一对应；函数型条目实现同名函数…
};
```
> 因为标了 `: Zh`，少一个键或类型不符 `type-check` 会直接报错——这是给你兜底的，照报错补齐即可。

### 2.4 组件用法 + 迁移已有 `zh` 直引
模板里：
```vue
<script setup lang="ts">
import { useI18n } from '@/i18n';
const { t } = useI18n();
</script>
<template>{{ t.chat.send }}</template>   <!-- t 是 ref，模板自动解包，直接 t.xxx -->
```
脚本里取值用 `t.value.chat.send`；插值函数 `t.value.chat.speakingWith(name)`。

**迁移**：`ChatView.vue` 和 `AppShell.vue` 目前是 `import { zh } from '@/i18n/zh'` 直引静态中文。改成上面的 `useI18n` 写法：模板 `zh.` → `t.`，脚本 `zh.` → `t.value.`。AppShell 的 `primaryNavigation` 是模块级常量、拿不到 composable，改成 `computed(() => [...])` 内用 `t.value.nav.*`。

### 2.5 语言切换 UI
放在设置页（波次 B）一个二级项「语言 / Language」：中文 / English 两选项，点选调用 `setLocale`。`localStorage` 已持久化，刷新保持。
